# 数据、API 与兼容契约检查标准

把契约理解为所有外部或跨边界依赖：不仅是 HTTP API，还包括数据库、事件、文件、命令行、配置、缓存键、SDK、序列化格式和隐含行为。

## 目录

1. 契约清单

3. 事件与消息

## 1. 契约清单

对每个契约记录：

- 生产者、消费者、所有者和联系途径
- 当前版本、仍在使用的最老版本和支持窗口
- schema 或格式来源、兼容规则与验证工具
- 延迟、吞吐、错误、顺序、幂等和事务语义
- 敏感等级、保留期限和地域/合规约束
- 变更与退场流程，以及能证明无人使用的遥测

未知消费者是风险项，不是删除旧接口的许可。

## 2. API 与 SDK

检查：

- 路径、方法、状态码、错误体、分页、排序、过滤和默认值是否稳定。
- 可选字段变必填、字段重命名、枚举收紧、数值范围变化是否会破坏旧客户端。
- 新字段是否会被严格反序列化客户端拒绝。
- null、缺失、空集合和零值语义是否一致。
- 重试安全、幂等键、超时和限流头是否定义。
- SDK 是否与服务版本锁死；二进制/源代码兼容是否需要单独保证。
- 弃用是否有遥测、通知、替代方案、期限和删除条件。
- 权限变化是否被误当作“兼容”而静默扩大或缩小访问。

## 3. 事件与消息

检查：

- 事件名和字段表达已发生的稳定事实，还是内部对象快照。
- 消费者是否容忍新增字段和未知枚举；生产者是否仍提供旧必填字段。
- schema registry、版本规则和契约测试是否覆盖真实消费者。
- 重复、乱序、延迟、重放、毒消息和死信处理是否定义。
- event id、聚合 id、发生时间、发布版本和关联 id 是否足够对账。
- 更正/撤销事件如何表达；是否依赖删除历史消息。
- 消费者升级失败时能否暂停、回放和恢复。

## 4. 数据库与存储格式

检查：

- schema 变更是否支持新旧应用版本同时运行。
- 列类型、默认值、约束、索引、触发器和排序规则变化是否锁表或改语义。
- 应用是否依赖未声明的列顺序、隐式转换、数据库时区或特定查询计划。
- 多个应用是否直连并写入同一表；谁有权迁移。
- JSON/blob 中是否藏有未版本化的 schema。
- 文件名、目录结构、对象 key、缓存 key 和序列化类名是否构成持久契约。
- 备份是否可恢复；恢复演练是否覆盖 schema 与应用版本配对。

## 5. 历史数据与数据质量

检查：

- 现存数据是否满足当前代码假设；抽样与全量分布是否不同。
- 遗留枚举、孤儿记录、重复、非法日期、编码、截断、精度和时区问题。
- 主键是否稳定；合并、拆分和重新编号是否破坏外部引用。
- 业务不变量如何转化为对账查询，例如余额守恒、订单金额一致、状态转换合法。
- 迁移是否保留审计链、创建/更新时间和来源标识。
- 删除、匿名化、保留和 legal hold 是否在复制与备份中一致。
- 训练、测试和日志数据是否含真实敏感信息。

## 6. 配置、命令行和运维契约

检查：

- 环境变量、配置键、默认值、优先级和动态刷新语义。
- 启动参数、退出码、stdout/stderr 格式和脚本依赖。
- 仪表盘指标名、日志字段、告警标签和 runbook 自动化是否依赖旧格式。
- feature flag 的默认值、生命周期、离线行为和租户覆盖。
- 部署模板、secret 名称、端口、健康检查和文件挂载路径。

这些契约经常没有正式消费者清单，变更前需要代码搜索、部署清单和运行遥测联合确认。

## 7. 兼容性验证

至少采用适用项：

- 生产者与每个受支持消费者版本的契约测试
- 新应用读旧数据、新应用写入后旧应用读取的交叉测试
- schema diff 与允许/禁止规则
- 黄金文件或序列化快照测试
- 事件回放、重复和乱序测试
- 真实数据脱敏样本与异常分布测试
- 双版本滚动部署、回滚和恢复演练

兼容结论必须明确方向：向后、向前、读兼容、写兼容、线协议兼容或行为兼容。只写“兼容”是不完整的。

## 8. 高危信号

- 生产迁移只能向前，应用却声称可回滚
- 同一部署同时重命名列并切换所有读写
- 双写没有幂等、补偿和对账
- 旧消费者没有遥测却计划删除字段
- 历史数据未分析就增加非空/唯一约束
- 事件 schema 变化依赖所有消费者同日发布
- 回填脚本无断点续跑、速率限制和结果校验
- 数据复制后没有权威源和冲突规则

发现上述信号时，不实施收缩或切流，转入 compatibility-data-migration.md 的迁移设计。
